# 自动任务派发

启动 FastAPI 后，每 5 秒执行一次调度。有效预约生成 pending 任务；按预约时间排序，为已连接 control WebSocket、启用且空闲的车辆批量预留任务。无可用车辆时保持等待，前端通过现有查询接口获取状态。

服务端下发 `dispatch_task` 时携带稳定的 `command_id`。车辆应按 `command_id` 去重，并回传 `{"type":"task_accepted","task_id":1,"command_id":"..."}`；服务端收到确认后才将任务和快递切换为配送中。未确认指令每 5 秒重试，最多三次且最长保留 20 秒，超时会释放车辆和任务供下一轮重派。

服务端每 5 秒发送 `heartbeat`，车辆可回复 `{"type":"heartbeat_ack"}`；任意合法 control 消息也会刷新存活时间。15 秒未收到消息即判定离线。执行中车辆断线后保留 30 秒重连宽限，宽限结束将派发状态标为 `interrupted`，不会把同一运行中任务改派给其他车辆。原车辆重连时会收到同一 `command_id` 且 `resume=true` 的任务，重新确认后恢复配送。

收到 `task_completed` 后，同步任务、快递、预约、派发指令和车辆状态，再分配下一单。重复完成回传不会释放正在执行其他任务的车辆。

预约改期和地址修改同步到 pending 任务；取消预约会取消待派发任务并解除快递绑定。任务开始执行后不允许修改预约。创建预约校验快递归属并拒绝重复有效预约。

管理员仍可通过 POST /api/dispatch/run 立即执行一次调度。

当前 WebSocket 连接保存在进程内，部署时使用单 worker：

```sh
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

重连会重发相同的 `task_id` 和 `command_id`。当前连接、心跳和调度锁保存在进程内，多 worker 部署前需要迁移到共享基础设施。升级既有数据库前执行 `alembic upgrade head`。地址仍使用现有任务字段，不在本次改动中加入自动地理编码。预约时间作为排序和预计完成时间，不作为开始派发的时间门槛。
